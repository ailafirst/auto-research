## 1. 背景与要验证的问题

项目是面向中英文资料的 Deep Research 系统：实时搜索、抓取、构建证据、分析、核查，动态、任务级语料
（按 `task_id` 隔离，Qdrant 向量 TTL 7 天），不是预先建好、长期反复查询的企业知识库。

此前 GraphRAG-V 实验（chunk 余弦相似度连边 + Louvain 社区）已证伪：指标不动，faithfulness 反而下降。
本轮验证的是不同机制——**LLM 抽取实体级关系**（而非 chunk 相似度图），要回答的核心问题：

> 实体级关系图能否恢复「dense + 跨语言双路 + reranker」这条强基线拿不到的桥接证据，且不引入忠实度回退？

## 2. 选型（2026-09-05）

五候选加权评分（工程成熟度 0.22、集成成本 0.20、动态语料成本适配 0.18、关系证据增益潜力 0.15、
运维复杂度 0.13、中英消歧 0.07、许可 0.05）：

**Neo4j GraphRAG Python SDK 3.75** > LightRAG 3.19 ≈ 自研轻量证据图 3.17 > FalkorDB 2.62 >
Microsoft GraphRAG 2.60 > HippoRAG 2 2.49。

首选 Neo4j SDK（`QdrantNeo4jRetriever` 精确对应"Qdrant 留向量、Neo4j 存关系"的目标形态），自研轻量
证据图作并行对照组（不采纳双路线并行 POC，避免决策空转）。

## 3. 两轮快速验证 spike（2026-09-05～06）

**v1（naive 管线）**：5 条人工多跳 QA，多跳召回未达标（top-10 更差，12 个桥接候选无一命中 gold），
建图耗时超预算（150 chunk 已 358.8s，全量外推 44 分钟超 1800s 超时）。诊断定位到 3 个可修缺口：
抽取只产表层短语不产规范实体、无实体消歧、遍历零精度控制（hub 实体把 48-64% 语料连在一起）。
**没有一条指向"图结构对深度研究无效"**。

**v2（补齐管线重测）**：三个缺口全部修复后，图桥结构性成立从 1/5 提升到 **6/6**——图确实建对了。
但检索指标仍无提升（chain@10 打平或更差）。根因：**这个任务的 dense 基线本身没有召回缺口**——6 条
多跳 QA 每条腿在基线里的排名除一条外全部 top-4，图没有"缺失的腿"可补。

## 4. 正式四层评测 L0-L3（2026-09-06）

针对 v1/v2 评测方法的缺陷（样本量不足、QA 手工构造偏向图能答的问题、只测检索一层、无统计检验）
重新设计：图路径 grounded QA + 必要性校验、bootstrap CI + McNemar 配对检验、L0（图构建）/L1（检索）
/L2（推理）/L3（成本）四层解耦。

| 层 | 关键指标 | Go 阈值 | 实测 | 判定 |
|---|---|---|---|---|
| **L0** 图构建质量 | 实体F1/关系F1/消歧召回/桥接可达 | 0.70/0.50/0.80/0.80 | 0.53/0.27/0.57/**1.00** | ✗ 3/4 门不达标 |
| **L1** 检索质量 | 多跳完整证据链命中率提升 | ≥8pp 且 p<0.05 | 最好 +4.4pp，p=0.69 | ✗ |
| **L2** 推理质量 | 多跳正确性/矛盾检测提升 | ≥10pp | +0pp / +0pp | ✗ |
| **L3** 运营成本 | 查询期开销/429率/增量成本 | <500ms/<5%/<30% | 3461ms/18%/~130% | ✗ |

判定前提：L0 通过 + (L1 或 L2 通过) + L3 通过才推进完整 POC。**四层全部未过**。

一句话结论：图的机制确实在起作用（L1 有 7/45 QA 靠图捞回 dense 完全漏掉的证据），但量级不足以移动
任何硬指标；同时评测本身存在若干工程缺口（见 §5）。

## 5. 工程复核与补齐方案（2026-09-06～07）

复核发现四层评测跑的是**未调优的最朴素实现**，若干问题是工程缺口而非结构性结论：图打分函数不含
问题语义（无 query-关系相关性项）、Arm-B 候选池被截断成对照混杂因素、抽取无重试无失败追踪、实体
消歧合并会主动制造 hub（63% 实体是 singleton）、查询期 3.5s 从未做过 `PROFILE` 拆分。

**阶段 0**（候选池截断修正 + 等成本对照重验）：修正后 chain@10 仍无提升，但四段可达性拆分把缺口
精确定位到打分函数（57%）和种子覆盖（30%）——不支持直接停止，指向继续修打分函数。

**阶段 A-D**（消歧质量修复 / 判定门槛复验 / 检索成本优化 / Neo4j 工程实践验证）：

- 阶段 A：消歧信号改进（结构 Jaccard + 模糊匹配）把 pairwise_recall 从 0.389 提到 0.435，方向正确
  但未过 0.50 验收线。
- **阶段 B（判定门槛）：结论"停止"**——全量语料 + 改进消歧后重跑，multihop chain@10 四臂仍完全
  一致（McNemar b=0,c=0）。
- 阶段 C：检索延迟优化验证有效（去重+top-80 预筛后 p95 从 13012ms 降到 1473ms），但不改变阶段 B 的
  停止判定，且并发扩展性瓶颈基本未变。
- 阶段 D：索引（task_id 范围化 PROFILE 验证）、批量写入、多租户过滤三项工程实践验证通过。
- 阶段 E（生产集成）：未执行。

## 6. Global Search 补测（2026-09-08）

调研发现 §3-5 全部测的是 **Local Search**（多跳事实检索命中率），而 GraphRAG 文献里实测有效的是
**Global Search**（LLM 建图 → 社区检测 → 分层摘要 → map-reduce 回答综述型/归纳型问题），本项目
从未实现也从未测过——两者是图的不同能力维度，不冲突。

补建组件：社区检测（networkx Louvain）+ 摘要 + Global Search map-reduce 查询 + dense baseline
等成本对照 + rubric 覆盖率评测方法（原子化关键点清单逐条判定，替代 Microsoft 论文原始的 LLM
pairwise 打分）。按用户选定的方案二（多语料并行）在 4 个主题差异很大的语料上验证：

| 任务 | 语料主题 | 抽取实体数 | 社区数 | graph 覆盖率 | dense 覆盖率 | delta |
|---|---|---|---|---|---|---|
| 01 | LLM 推理加速（schema 对齐域） | 1710 | 55 | 0.963 | 0.963 | 持平 |
| 03 | 量子计算基础 | 568 | 25 | 0.821 | 0.911 | -0.090 |
| 11 | 微服务 vs 单体 | 133 | 16 | 0.875 | 0.911 | -0.036 |
| 06 | PIPL vs GDPR（法律） | **16** | 4 | 0.653 | 0.958 | -0.305 |
| **总体（12题）** | | | | **0.828** | **0.936** | **-0.108** |

即使在实体抽取 schema 专门适配的 task01 上，Global Search 也只是打平 dense baseline，没有一题反超；
其余三个任务全面落后，且**领域匹配度越低、图谱越稀疏，差距越大**。成本上图方案每题平均调 LLM
≈26 次（遍历全部社区 map + 1 次 reduce），dense baseline 每题固定 1 次——**覆盖率没有增量，成本
反而是 26 倍**。

副产品发现：POC 阶段的实体/关系抽取 schema 是纯手工针对 task01 标注的封闭词表，从未做跨域泛化。
task06（法律语料）1029 个 chunk 里 99.8% 被判定"无可抽取实体"，全语料仅抽出 16 个实体——这是 POC
阶段的工程缺口（生产级实现通常按语料动态推断实体类型），不是 Global Search 机制本身的问题，但也
说明跨域复用图 RAG 的门槛比预期更高。

## 7. 最终结论

**两轮独立测评——Local Search（多跳事实检索命中率）和 Global Search（综述覆盖率）——均为负向
结果，且都伴随数倍到数十倍的额外成本。判定：GraphRAG 不进生产线，本轮实验到此终止，不再新开
验证维度。**

这不是"图检索对本项目场景绝对无效"的无条件结论，已知的边界条件：

- 语料规模是单主题 ~1400 chunk 级别，Microsoft 原论文验证 Global Search 用的是百万 token 级、
  多层次分层摘要的语料——本项目规模可能还没到图的摘要聚合相对"直接检索更多 chunk"产生优势的
  临界点，但连续两轮负结果 + 高成本不支持继续验证第三个维度来确认这一点。
- 7 天 TTL 的动态任务级语料，建图成本本身就难以摊薄，这是独立于检索效果之外的硬约束。
- 若未来语料规模、问题类型、复用周期发生数量级变化，可重新评估，起点是本文 §5-6 定位的具体
  工程缺口（打分函数缺 query 语义、schema 未跨域泛化等），而非从零调研。
