# 版本说明 v0.1.6

> 发布日期：2026-07-06 · 上一版本：[v0.1.5](版本说明_v0.1.5.md) · 对比基线：commit `d5e9f5c`

本版本单一主线：**用 Query Rewriting 把检索 Recall 再抬一档**。在 v0.1.5 已建立的确定性黄金集上 A/B 三种改写策略，最终以 **HyDE** 把生产检索的 **Recall@6 从 0.892 提升到 0.908（+1.7pp）**。延续 v0.1.5 的方法论——按冻结基准逐项 A/B、记录负结果，Keyword 扩写与 HyDE+Keyword 融合两条方案经实测被否决并归档。

## 二、HyDE（本版核心）

**原理**：对子问题先让 LLM 写一段 2–3 句、技术风格的**假设性答案段落**（英文），用这段"理想答案"而非原始疑问句去做 dense 检索。假设段落自带领域术语，与英文 gold 文档的向量对齐远好于一个中文疑问句。

**怎么做的**：所有 query 统一走「改写 → 翻译 → 检索」管道——

```
子问题（中文）
  ↓ QueryRewriter（HyDE 模式）
  ├─ 原始 query（中文）
  └─ HyDE 假设段落（英文，2–3 句技术风格）
  ↓ xling 双路（逐 query 判断——含中文才翻译）
  ↓ 批量 Embed + 并行 Search
  ↓ 按 chunk 合并取最高分 → Reranker → top-k
```

**恢复案例**（HyDE 救回的 2 条 miss）：
1. Task 01（LLM 推理加速）：*"有哪些减少大模型 KV Cache 大小的常见算法？"* → 假设段落列出 MQA / GQA / sliding window / sparse attention，锚定相关文档。
2. Task 02（Python vs Rust）：*"Rust 在构建 WebAssembly 时如何与 JavaScript 进行数据交换？"* → 假设段落的 wasm-bindgen / serde 术语锚定检索。

## 三、否决的方案（均有实测）

| 方案 | 实测结果 | 否决原因 |
|------|----------|----------|
| **Keyword 扩写** | +0.8pp | 增益偏低，且恢复的 miss 与 HyDE 不重叠，无组合价值 |
| **HyDE+Keyword 融合** | +0.8pp（不及 HyDE 单独 +1.7pp）| 5 路 query 并行检索引入噪声：向量 Recall@40 从 0.917 **暴跌至 0.817（−10pp）**，不相关关键词把 gold 挤出候选池，reranker 仅部分修复 |

> **机理教训**：HyDE 的单一假设段落是**语义空间聚焦**（缩窄到理想答案邻域）；多路关键词是**语义空间拓宽**（引入噪声）。检索召回受益于聚焦而非发散。

## 五、冷启动 & 降级

- LLM 改写调用失败 → 静默返回空列表，降级为原始 query 检索。
- 改写产出的 HyDE 段落为空 → 降级为原始 query。

全链路保持 v0.1.x 一贯的"降级安全"风格：改写是**增益项而非必需路径**，任何一步失败都退回 v0.1.5 的双路检索，功能不受影响。
