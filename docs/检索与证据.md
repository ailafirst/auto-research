## 一、全链路诊断：根因不在写作层

案例 `task_1f68fea82388`（2026-07-18）：*"2026 年脑机接口最新研究方向有哪些，哪些值得深入研究"*。用户反馈报告散、没答到关键问题。逐节点定责：

| 节点 | 判定 | 依据 |
|---|---|---|
| Planner | ✓ 正常 | 5 个子问题，q5 精准命中"哪些值得深入" |
| **搜索/证据** | **✗ 根因** | 20 条采纳信源里 ~18 条是市场报告 / 产品 PR / 趋势博客，真·科研文献仅 1 条 |
| 补充轮 | ✗ 帮倒忙 | issue 从第 1 轮 6 条涨到第 2 轮 14 条（发散）：先漂向商业化，再去追 analyst 编造的 claim |
| Analyst | ✗ 无源硬编 | 多处 `[C??]` 占位却仍以 0.85 置信度断言，编出信源里根本没有的数字 |
| Fact-checker | ✓ 正常 | 14 条全部抓到，标为 `insufficient_evidence` / `overclaim` |
| Report-writer | ✗ 次要 | 被标记的 claim 全剥掉后只剩泛泛框架；q5 的答案只在摘要出现一次 |

Tavily 给 SEO 化的市场页打了最高分（0.94 / 0.929 / 0.917），挤占了候选池——**证据池讲的是"市场规模 / 产品发布"，用户问的是"研究方向的科学评价"，答不到点上从证据就注定了。**

四项改进及其去向：

| 方案 | 落点 | 状态 |
|---|---|---|
| ① Analyst 无源硬编纪律（禁 `[C??]` 断言 + 置信度联动） | analyst 提示词与结构化输出 | 见 [LLM 节点改进](LLM节点改进.md) |
| ② 搜索偏置权威信源 | `search_service` | **本文 §三**（放弃按 intent 分类，改统一注入） |
| ③ 补充轮只补真实证据缺口 | `research_runner` | 见 [v0.2.1](version/v0.2.1.md) 多轮增量补证 |
| ④ 报告按问题类型定形 | report_writer 提示词 | 见 [v0.2.1](version/v0.2.1.md) tier-A |

## 二、搜索层工程（v0.1.2）

### 1. Retriever V4：展平时打标

V1 全并发但结果不知道属于哪个子问题；V2 串行子问题拿到归属却慢 3.4×；V3 并发 + Semaphore 恢复了速度但嵌套复杂。**V4 的洞察是归属信息该在展平时注入，而不是在查询时维护分组结构**：

```python
tagged = [(q, sq["id"]) for sq in sub_questions for q in sq["search_queries"]]
# 每条结果天然带上 sub_question_id，全部查询仍完全并发
batches = await asyncio.gather(*[_search_tagged(q, sid) for q, sid in tagged],
                               return_exceptions=True)
```

耗时回到 V1 的 ~8.2s/题，限速控制下移到 `SearchService` 层。

### 2. Tavily 接入

- **`raw_content` 跳过爬取**：Tavily 随搜索结果返回完整正文（1–4 万字符），覆盖率 100%，`content_extractor` 从 ~15s 降到 ~0s。只有无 `raw_content` 的 URL 才走爬虫（即 DDG 降级路径）。
- **`tavily_score` 替换启发式评分**：原先用 `content_length / 3000` 代理相关性，外加 credibility=0.7、freshness=0.8 两个**固定常量**（等于没有信息量），已全部移除。现直接用 Tavily 语义分，`accepted = score >= 0.5 and length > 50`；DDG 路径才回退长度启发。
- **`search_summaries` 注入 analyst**：Tavily 每次搜索附带的 AI 摘要按 `sq_id` 收进 `state["search_summaries"]`，分析每个子问题时 LLM 同时看到 ① RAG 检索片段 ② Tavily 摘要基线。

### 3. 零结果三层防护

根因是 Tavily dev key（`tvly-dev-*`）高并发触发限速，而原实现有三个缺陷叠加：`TavilyProvider.search()` 吞掉所有异常返回 `[]`（`@retry` 永远看不到异常）、Semaphore 无间隔仍有突发、零结果静默丢弃。

```
TavilyProvider.search()
  ├─ Semaphore(3)                        最多 3 并发
  ├─ finally: sleep(0.3)                 请求成功也执行，全局约 10 QPS
  └─ 限速关键词 → 抛 TavilyRateLimitError  ("excessive"/"rate"/"blocked"/"429"/"too many")
SearchService._primary_search()          ← @retry 在此层才生效
  └─ 指数退避重试 3 次（2–30s）
SearchService.search()                   ← 最终降级
  └─ 重试耗尽或结果为空 → DuckDuckGo 兜底
```

三点设计取舍：降级是 **per-query** 的，不影响其他并发查询继续用 Tavily；`sleep(0.3)` 放 `finally` 保证成功路径也限速；retry **只针对** `TavilyRateLimitError`，网络超时不重试。

### 4. 多轮 Retriever 与 LLM 超时

- 第 2 轮 `follow_up_queries` 非空时只搜补充方向，不重复第 1 轮关键词（修复前 planner 会覆盖 `follow_up_queries`，第 2 轮等于原样重做第 1 轮，详见 [LLM 节点改进 §五](LLM节点改进.md)）。
- `litellm.acompletion(timeout=120)`：此前 `fact_checker` 调 LLM 无超时，服务响应慢时任务永久卡在 75%，既不 failed 也不 complete。

## 三、信源构成：学术双路（v0.2.1）

§一 的根因是"权威研究源进不了候选池"。一个被**否决**的直觉方案是按 `research_strategy.intent/domain` 判断该不该加学术源——分类会错、要维护规则、脆。目标改为**统一生效、与"猜测问题类型"解耦**，相关性一律交给已有的 bge-reranker 自过滤。

| | 方案① Tavily 学术双路 | 方案② OpenAlex |
|---|---|---|
| 机制 | 通用搜索之外**再并发一路 Tavily，限定静态学术白名单域**（arxiv/pubmed/*.edu/nature…），结果合并 | 并联 OpenAlex（2.5 亿论文，免 key），论文"标题+摘要"入池 |
| 依赖 | 零新依赖（Tavily 已接） | 新增一个外部 API |

### 实验数据

三支脚本（`rag_experiments/`，均不改生产代码）跑 2 个研究题（脑机接口、固态电池）+ 1 个工程对照题（React state management）。**核心度量是研究类信源在 rerank 后 top-10 的占比**——那才是真正到 analyst 面前的构成；对照题用于检验补偿手段是否破坏了非研究题的 self-filtering。

| 问题 | 类型 | 候选池研究占比 base→①→② | **rerank top-10 base→①→②** |
|---|---|---|---|
| bci | research | 10%→50%→55% | **20%→30%→20%** |
| battery | research | 22%→55%→62% | **20%→50%→20%** |
| react | control | 0%→57%→55% | **0%→10%→0%** |

候选池层面两者几乎打平，**top-10 层面 ① 有效抬升、② 形同没加**。查 rerank 原始分即知原因：研究题上 academic-web 与 web 同档（0.428 vs 0.562 / 0.855 vs 0.867），唯独 **OpenAlex 整段摘要被压到 ≈0**（中位 0.000）；而对照题上 academic-web 也被正确压低到 0.25——**reranker 判的是"是否对口"，不是"是否学术"。**

两条补救路线均告失败：

- **事后融合救 ②**：能把论文救回 top 的策略（zscore / RRF / 硬配额）**同时把工程对照题的研究占比从 10% 拉到 40–70%**，self-filtering 被打爆。本质是"不管相不相关都保证每条车道露脸"。
- **换粒度救 ②**：整段摘要改切句取最高分，最佳论文确实抬了不少（bci 0.199→0.554），**但没有一篇越过 top-10 分数线，中位仍 ≈0**；且提升最大的全是综述/展望类，primary 论文照样 ≈0。

> **结论：所谓"reranker 的短板"大部分不是 bug，是它判对了。** 对"研究方向 / 哪些值得深入"这类 meta·评价题，**综述才是对口证据，单篇 primary 论文本就是弱匹配**——切不切 chunk 都一样。① 胜在喂给 reranker 的是"对口的综述网页"，② 输在喂的是"被正确判为弱匹配的论文摘要"。方案② 搁置，唯一可能翻案的角是**具体事实型子问题**（取数/核查），未验。

### 落地

设计原则：统一生效、零新依赖、降级安全、仅 Tavily 路增强（DDG 不受影响）。

- `ACADEMIC_SEARCH_ENABLED`（默认 `true`）+ `ACADEMIC_ALLOWLIST`（`search_service.py` 模块常量）
- `SearchService.search_academic_dual()`：**并发**跑通用一路 + 白名单一路，按 URL 去重合并（通用优先、学术补新）；非 Tavily 或学术路失败/为空时退回通用结果
- `SearchService.search(..., include_domains=)`：**缓存 key 必须纳入 `include_domains`**，否则与通用搜索的缓存串味
- `retriever_node._search_tagged`：开关开启且 provider=Tavily 时才走双路

成本是每查询多一次 Tavily advanced 调用（约 +1× credit）。验收看两头：评价型问题的 top-K 研究占比显著上升（预期 +20~30pp），**同时**工程/事实型问题基本不变（护栏，对照题 ≤ +10%）。
