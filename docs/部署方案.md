# 部署方案（初步）— 全栈本地部署 + 腾讯云仅作内网穿透

> 目标拓扑：**所有服务（含 Nginx、TLS、前端静态、API、模型服务）全部运行在本地 GPU 机器上**；
> **腾讯云服务器仅作内网穿透（frp）中转**——只转发 TCP 字节，不承载任何应用、静态资源或 TLS。
>
> 适用前提：一台可 24/7 常开的本地 GPU 机器（当前开发机），已有 ICP 备案域名。

---

## 1. 为什么用这个拓扑

| 好处 | 说明 |
|---|---|
| 复用本地 GPU | 模型服务（bge-m3 + reranker + opus-mt，FP16）跑在 RTX 4080 上，**不必租云 GPU**。 |
| 绕开家宽无公网 IP | `frpc` 由本地**主动拨出**到云端 `frps`，本地无需公网 IP、无需端口映射，天然穿 NAT。 |
| 数据/密钥全留本地 | SQLite、`output/`、TLS 证书、API key 都在本地，云端看不到任何明文。 |
| 云端最省最简 | 云侧只跑 `frps`，**1 vCPU / 1~2G 足够**，成本极低；一次配好基本不用维护。 |
| 出海问题不在云端 | LLM / Tavily / 抓取都从**本地网络**出口——本地已跑通即可。 |

### 取舍与风险（需正视）
- **可用性 = 本地机器常开**：断电、重启、宽带波动都会让服务下线。
- **家宽上行带宽**：**全部**用户流量（含前端静态首屏）都要经隧道从本地上行返回，比「静态放云端」方案更吃本地上行。前端体积小、报告是文本，一般家宽可扛，但大并发时受限。
- **本地 Windows 常驻**：需把全栈 + Nginx + frpc 做成开机自启 + 崩溃自拉（§6.B）。
- **迁移退路**：全栈已服务化 + 环境变量驱动，日后要整体迁云 GPU 实例，改动很小（§10）。

## 2. 组件与职责划分

### 云端 CVM（**仅内网穿透**）
| 组件 | 作用 |
|---|---|
| frps（frp server） | 唯一服务。接受本地 frpc 拨入，把云端 `80/443` 的 TCP 连接**原样转发**给本地 Nginx |
| 域名解析 | 备案域名 A 记录指向云 CVM 公网 IP（备案绑定在云 IP 上） |

> 云端**不装 Nginx、不放证书、不放静态、不做 TLS**。它只是一根加密管子。

### 本地 GPU 机器（承载全部服务）
| 组件 | 进程 | 端口 | 说明 |
|---|---|---|---|
| Nginx | 本地 | 80/443 | **TLS 终结 + 前端静态托管 + `/api`,`/health` 反代到 8000** |
| 前端静态 | `web/dist` | 由本地 Nginx 托管 | — |
| API | `uvicorn app.main:app` | 8000 | 仅本地回环，Nginx 反代 |
| 模型服务 | `uvicorn app.model_server:app` | 8100 | GPU + FP16，仅本地回环 |
| Worker 池 | `arq app.worker.WorkerSettings` | — | 每 worker ~0.75G |
| Redis | docker / WSL | 6379 | 队列 + 限流 + 缓存 + 热层进度，仅本地 |
| SQLite | 文件 | — | `output/deepresearch.db` |
| frpc（frp client） | — | — | 拨出到云端 frps，暴露本地 `80/443` |

> 经隧道对外的只有本地 Nginx 的 `80/443`；API 8000、模型服务 8100、Redis 6379 只在本地回环，永不进隧道。

## 3. 网络与数据流

```
   用户浏览器
      │  https://你的备案域名  (443)
      ▼
┌──────────────── 腾讯云 CVM（仅 frps）────────────────┐
│  frps ：把 :80/:443 的 TCP 连接原样转发（不解 TLS）    │
└───────┬──────────────────────────────────────────────┘
        │  frpc 主动外连（穿 NAT，无需本地公网 IP）
        │  建议开启 PROXY protocol 以透传真实客户端 IP
┌───────┼──────────────────── 本地 GPU 机器 ────────────────────┐
│  frpc → 本地 Nginx :443                                        │
│  本地 Nginx                                                    │
│    ├─ /              → web/dist 静态                            │
│    └─ /api, /health  → 127.0.0.1:8000                          │
│                              │                                 │
│  API :8000 ──► 模型服务 :8100 (RTX 4080, FP16)                 │
│      │         Worker × N                                      │
│      └───────► Redis :6379    SQLite 文件                      │
│                                                                │
│  外部调用（LLM / Tavily / 抓取）从本地网络直接出口，不经云端    │
└────────────────────────────────────────────────────────────────┘
```

- **TLS 在本地终结**：证书放本地 Nginx，云端全程看不到明文。
- **前端零代码改动**：`api.ts` 用相对路径，页面与 `/api` 同域，本地 Nginx 按前缀反代到 8000。
- **隧道用 frp TCP 透传 80/443**：云端不碰 HTTP/TLS，纯 TCP 转发；开 `proxy_protocol` 让本地 Nginx 拿到真实客户端 IP（否则日志/限流只看到隧道地址）。

## 4. 资源清单

### 云端 CVM（极简）
- 规格：**1 vCPU / 1~2G / 40~50G 系统盘**（只跑 frps）。
- 带宽：按量或固定 **5~10 Mbps**；承载全部经隧道回传的用户流量。
- 系统：Ubuntu 22.04。
- 安全组：**只放行 22 + frps 接入端口（7000）+ 对外业务端口 80/443**。

### 本地机器（现状即可）
- RTX 4080 16G / 32G 内存 —— 本 session 已验证可跑「模型服务 + 多 worker」全栈。
- **务必配 swap/页面文件并卡住 worker 数**，防止提交内存顶穿（本 session 排查过的崩溃）。
- 新增本地 Nginx（Windows 版）+ frpc。

### 外部依赖
- `LLM_API_KEY`（+ `LLM_BASE_URL`）：从本地出口。
- Tavily key 池（`tavily.txt`）。
- 备案域名（已有）+ TLS 证书（**证书在本地**签发，见 §5.B）。
- 模型权重：本地已缓存，无需处理 HuggingFace 镜像。

## 5. 部署步骤

### A. 云端 CVM（只做一次）
1. 系统准备：Ubuntu 22.04，非 root 用户，安全组放行 22 + 7000 + 80/443。
2. 装 frps：`bind_port=7000`、设强随机 `token`；放开 TCP 代理所需的 `80/443` 端口；systemd 自启。
3. 域名解析：备案域名 A 记录 → 云 IP。
4. 云端到此为止——不装 Nginx、不放证书。

### B. 本地 GPU 机器
1. **本地 Nginx**：
   - `root` 指向前端 `web/dist`；
   - `location /api/`、`location /health` → `proxy_pass http://127.0.0.1:8000;`；
   - 强制 HTTPS、gzip、可选 `limit_req` 限流；
   - 开 `set_real_ip_from` + `proxy_protocol` 读取 frp 透传的真实 IP。
2. **TLS 证书**（本地签发，二选一）：
   - **DNS-01（推荐，无需入站）**：用 acme.sh / certbot + DNSPod(腾讯云 DNS) API 令牌签发，通配或单域；不依赖端口连通，最适合隧道场景。
   - HTTP-01：需云端 frp 也把 `:80` 透传到本地，certbot 走 `.well-known` 验证。
3. **全栈常驻**（Windows 服务化，见下）：Redis → 模型服务 8100 → API 8000 → worker×N。
4. **生产 `.env`**：`APP_ENV=production`、`REDIS_URL=redis://127.0.0.1:6379/0`、`MODEL_SERVICE_URL=http://127.0.0.1:8100`、`QUEUE_ENABLED=true`、填 `LLM_API_KEY`、换掉 `SECRET_KEY`。
5. **frpc**：`server_addr=云IP`、同一 `token`；配置两条 TCP 代理把本地 `80/443` 暴露到云端 `80/443`，开 `proxy_protocol_version = v2`；自启 + 断线自动重连。
6. **Windows 常驻方案**：用 **NSSM** 把 `nginx` / `model_server` / `api` / `worker` / `frpc` 各包成 Windows 服务（开机自启、崩溃自拉）；Redis 用 Docker Desktop / WSL 常驻。

### C. 前端
1. 本地 `cd web && npm ci && npm run build` 产出 `dist/`（就放本地，由本地 Nginx 托管）。
2. 相对路径设计使 `/api`、`/health` 自动经本地 Nginx 反代到 8000，无需改代码。
3. 前端更新只需重 build，无需动云端。

## 6. 安全加固
- **frp**：必设强随机 `token`；仅透传 `80/443`；模型服务/Redis/API 绝不进隧道。
- **云端安全组**：只开 22/7000/80/443。
- **TLS**：本地 Nginx 全站 HTTPS + HSTS；证书私钥只在本地。
- **真实 IP**：`proxy_protocol` 透传，供本地限流/审计。
- **应用鉴权**：当前 API **无鉴权**。对外前建议至少 Nginx Basic Auth，或 API 层加 token/登录（面向公众需正式鉴权 + 配额）。
- **限流**：本地 Nginx `limit_req` + 后端已有 LLM 令牌桶控成本。

---

## 7. 可用性与运维
- **本地常开**：UPS 防断电；关自动重启/休眠；注意长时 GPU 负载散热。
- **隧道自愈**：frpc 断线自动重连；对 `https://域名/health` 做外部拨测告警。
- **备份**：定时备份本地 `output/deepresearch.db` 与 `output/tasks/`。
- **日志**：各服务 + 本地 Nginx access/error log 切割。
- **健康检查**：本地 `:8000/health`、`:8100/health`、`https://域名/health`。

## 8. 大陆特有事项（本拓扑下大多已化解）
- **ICP 备案**：已有备案域名 ✅，域名解析到云 IP 即满足 IP/DNS 层合规；隧道回本地为技术实现。
  （提示：部分场景对 内网穿透 + 备案域名 有合规口径差异，如面向公众正式运营，建议确认所在地政策。）
- **HuggingFace 被墙**：本地已缓存模型，无需镜像 ✅。
- **LLM 出海**：从本地网络出口，本地已跑通即可（不稳时于本地侧加代理，与云端无关）。
- **pip/npm 换源**：仅影响本地装依赖，用清华 PyPI + npmmirror 提速。

## 9. 待确认项（用于把方案定稿）
1. **LLM 后端**（当前「待定」）：域内网关 or 境外 OpenAI？决定本地侧是否加代理。

3. **本地机器 24/7 可行性**：能否长期常开 + UPS？否则考虑 §10 迁云。
4. **对外鉴权**：内部小范围还是公众？决定是否需要正式登录/配额体系。

## 10. 后续演进：平滑迁到云 GPU（可选退路）
若本地常开不现实或用户量上来，可整体迁到腾讯云 GPU 实例（GN7/T4）：
- 全栈已**服务化 + 环境变量驱动**，迁移主要是「换台机器跑同一套服务」，无需改代码；
- 届时前端/API/模型同机，**去掉 frp 隧道**，Nginx 直接反代本机 8000；
- 数据从本地 SQLite 迁移（或按 `DATABASE_URL` 切 MySQL 支持多机）。
