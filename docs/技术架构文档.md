# Deep Research Agent — 技术架构设计文档

> 当前状态对齐 v0.2.0。历史演进见 [版本说明系列](README.md#版本说明changelog)。

## 1. 系统架构

v0.2.0 起从"单进程内存任务"演进为"模型服务 + API + N×worker"的服务形态：

```
用户
  │
  ├─ React Web (web/, Vite+TS) ──┐
  └─ API Client (curl/httpx) ─────┤
                                  v
                          FastAPI Server (app/main.py, :8000)
                                  │  创建任务
                                  v
                     SQLite (SoR) ◀── TaskService ──▶ Redis (热进度/缓存/限流)
                                  │  入队
                                  v
                          arq 队列 (Redis)
                                  │  消费
                                  v
                     worker (app/worker.py, 可多进程) ──▶ research_runner.run_research()
                                  │                          │
                                  │                          v
                                  │                  LangGraph 研究流水线（线性 8 节点）
                                  │                          │
        ┌─────────────────────────┼──────────────────────────┼───────────────────┐
        v                         v                          v                   v
  Search (Tavily/DDG)     model_server (:8100)          Qdrant(内存)         LLM Provider
                          bge-m3 + reranker + opus-mt                        (LiteLLM/MiMo)
                          （一份 fp16 模型，HTTP 共享）
```

- **模型服务化**：`app/model_server.py` 独占一份 fp16 模型（embed/rerank/translate），worker 经 HTTP 共享，避免每 worker 各付 ~6.9 GB。`MODEL_SERVICE_URL` 为空时回退本地加载。详见 [模型服务化与显存内存优化.md](模型服务化与显存内存优化.md)。
- **降级安全**：Redis / arq 队列 / 模型服务 任一不可用都自动旁路（进程内执行 / 本地加载 / 跳过缓存），不阻断研究。

## 2. LangGraph 工作流（纯线性，无条件边）

图本身是**纯线性链**，无任何条件分支：

```
START
  → planner_node          分解研究问题为子问题 + 研究策略（intent/domain/depth）
  → retriever_node        多关键词并发搜索，按 sub_question_id 标记，全局 URL 去重
  → content_extractor_node 优先用 Tavily raw_content，否则抓取网页正文
  → source_evaluator_node  规则评估（无 LLM）：Tavily score≥0.5 / DDG 正文>300 字
  → evidence_builder_node  切片 → Embedding → Qdrant 入库（失败降级为原始文档）
  → analyst_node           RAG 检索证据，各子问题并发分析（共享 KV 前缀缓存）
  → fact_checker_node      并发核查证据充分性，判定是否需要补充
  → report_writer_node     生成最终 Markdown 报告
  → END
```

> **控制流不在图内**：多轮补充研究、引用修正都在 `app/services/research_runner.py::run_research()` 的外层 `while` 循环里，不是 LangGraph 的条件边。要改流程编排改 `research_runner.py`，不是 `builder.py`。

**图外控制流：**

```
run_research()                                  ← research_runner.py
  ├─ 第 1 轮：整图 astream → _revise_citations（引用不符时只重跑 analyst→fact_checker→report_writer）
  └─ while current_round < max_rounds:
        若 fact_check_passed 或无 follow_up → break
        否则携带 follow_up_queries 再跑整图（planner 在 round>1 跳过重规划）
```

## 4. 数据流

```
用户输入 → ResearchTaskCreate（校验）→ SQLite 建任务记录
  → research_runner 构造 ResearchState → LangGraph astream
      ├── research_strategy / research_plan / sub_questions
      ├── search_results / crawled_documents / evaluated_sources
      ├── evidence_chunks（Qdrant）/ citation_registry
      ├── sub_answers / fact_check_result
      └── final_report (Markdown)
  → 每节点：TaskService 写状态（SQLite）+ 热进度快照（Redis，裁掉大字段）
  → 完成：final_report 落 SQLite → API 查询返回
```

**Citation Registry**：每个被接受的来源分配稳定 `C01/C02…` id，是 analyst → fact_checker → report_writer 全链路引用的唯一真源。

## 5. 关键设计决策

### 5.1 异步 + 并发
- 全外部 I/O 走 `asyncio` + `httpx`；Qdrant 用 `AsyncQdrantClient`。
- LLM 调用经进程级 `Semaphore(LLM_MAX_CONCURRENCY)` 全局闸门（只包住网络调用，退避 sleep 不占额）；analyst/fact_checker 另有节点内并发上限。

### 5.2 多轮研究（图外）
- `fact_checker_node` 判定 `_SERIOUS_ISSUE_TYPES`（contradiction/overclaim/insufficient_evidence）触发补充轮次；`citation_mismatch` 走 analyst 修正而非新一轮。
- `research_runner.run_research()` 外层 `while` 循环控制，`max_rounds` 定深度。

### 5.3 LLM 调用
- LiteLLM 统一接口，自定义 `LLM_BASE_URL` 自动给模型加 `openai/` 前缀。
- 结构化输出用 JSON-schema `response_format`（analyst/fact_checker）。
- 失败 tenacity 3× 指数退避；`_llm_with_short_retry` 防截断/空输出。

### 5.4 可扩展性
- 搜索经 `USE_TAVILY` 切换 provider；embedding provider 经 `EMBEDDING_PROVIDER` 可插拔（st/fastembed/api）。
- SQLite 经 `DATABASE_URL` 可切 MySQL/PostgreSQL；Qdrant 可切持久模式（改构造函数）。
- 提示词为 `app/prompts/*.md` 可编辑文件。
